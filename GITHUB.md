# HeatShield — getting this onto GitHub

Everything you need is inside `heatshield.zip`: source, data, tests, a `.gitignore`, a `LICENSE`
(MIT), GitHub Actions CI, and `AGENTS.md` so the next AI agent understands the codebase
immediately.

**Do this once, before anything else:** extract the zip. It unpacks to a single folder
`heatshield/`. All commands below assume you are inside it.

---

## What's in the bundle (101 files, ~1.9 MB)

| | |
|---|---|
| ✅ Included | `core/`, `app/`, `scripts/`, `tests/`, `frontend/web/src`, `data/`, `requirements*.txt`, `.vscode/`, `.github/`, `LICENSE`, all docs |
| ❌ Excluded | `.venv/` (851 MB), `node_modules/`, `logs/`, `.env`, `frontend/web/dist/`, `__pycache__`, OSM dumps |

The excluded things are regenerated by `pip install` and `npm install` — they must never be
committed.

> **The `.gitignore` was broken and has been fixed.** Git allows **one pattern per line**; the old
> file had `.venv/ venv/ env/` on a single line, which matches nothing. Had you run `git add -A`,
> git would have tried to commit the entire 851 MB virtualenv and GitHub would have **rejected the
> push** (hard limit: 100 MB per file). It now reads `.venv/`, `venv/`, `env/` on separate lines.
> `.vscode/` is intentionally *not* ignored — `launch.json` and `tasks.json` are project assets.

## Option 0 — One command (easiest)

The bundle ships two scripts that do all of the git work for you:

| OS | Run |
|---|---|
| macOS / Linux | `chmod +x push-to-github.sh && ./push-to-github.sh` |
| Windows | **double-click `push-to-github.bat`** |

They ask for your repository URL and then run `git init` → `add` → `commit` → `push`. They also
**refuse to continue** if `.venv/`, `node_modules/` or `.env` would be uploaded, so a broken
`.gitignore` can't silently cost you a rejected push.

Still do this first: create an **empty** repository at **github.com/new** (no README, no
`.gitignore`, no license).

---

## Option 1 — Command line (recommended, ~30 seconds)

1. Create the repo on github.com → **New repository**.
   ⚠️ Leave it completely **empty** — do **not** tick "Add a README file", "Add .gitignore" or
   "Choose a license". We already ship all three, and GitHub's versions would collide with your
   first push.

2. Then:

```bash
cd heatshield

git init
git add -A
git status            # sanity check - see the warning below

git commit -m "HeatShield: extreme heatwave early warning + human thermal stress index"

git branch -M main
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

**Sanity check before you commit** — `git status` should list ~101 files. If you see thousands of
files under `.venv/` or `node_modules/`, the ignore rules aren't applying; stop and fix that
first.

If GitHub asks for a password, it wants a **Personal Access Token**, not your account password
(Settings → Developer settings → Personal access tokens → Tokens (classic), scope `repo`).

---

## Option 2 — GitHub Desktop (no terminal)

1. Extract the zip.
2. GitHub Desktop → **File → Add Local Repository** → choose the `heatshield` folder.
   (If it says the folder isn't a git repository, choose *create a repository* — it will `git init`
   for you. Leave every other option unchecked.)
3. Commit all → **Publish repository** (uncheck "Keep this code private" if you want it public).

## Option 3 — Drag and drop in the browser (**don't — it silently breaks**)

⚠️ **This method failed in practice.** A browser upload of this project produced a repo with
**22 files out of 110** — every top-level file arrived, and *every nested folder was dropped*.
No `core/`, no `app/`, no `scripts/`, no `tests/`, no `data/`, no `frontend/`, no `.vscode/`,
no `.github/`. GitHub happily reported the commit as successful ("Add files via upload") and
the repo size as 0 KB.

The failure is quiet and looks like success. An AI agent pointed at that repo correctly reported
"documentation only, zero source code" and could verify nothing.

Three separate reasons it goes wrong:

- GitHub's web UI **will not extract a `.zip`** — it just uploads the zip as one file
- Dragging ~110 files at once is slow, and partial uploads commit without warning
- Folder structure and dotfiles do not reliably survive the drag

**Use Option 0 or Option 1.** If you've already uploaded this way, re-push properly: extract the
zip, run `push-to-github.sh` (or the `.bat`), and answer **y** when it asks to replace the remote
contents — it detects the partial commit and force-pushes the complete tree.

**Always verify afterwards:** the repo home page must show **~110 files**, and `core/`, `app/`,
`scripts/`, `tests/`, `data/` and `frontend/` must all be visible. If it says 22, the upload
silently failed again.

## After you push — verify it worked

1. **Actions tab** → the `CI` workflow should run and go green. It installs Python 3.11 + Node 20,
   runs the 52 tests, and builds the frontend. A green badge is itself a demo point.
2. **Check the file count on the repo home page** — it should say ~101 files, not thousands.
3. **Confirm `.venv/` is not there.** If you see it, the ignore rules failed; delete it from the
   repo and fix `.gitignore`.

## Handing it to another AI agent

`AGENTS.md` is the file that matters. It is the standard convention understood by Codex, Claude
Code, Google Antigravity/Gemini, Cursor and GitHub Copilot — they read it automatically when they
open the repo. It contains the architecture, the exact physics formulas, the invariants
(141 wards · 20,304 ward-hours · 846 ward-days · 52 tests), the hard constraints (never fabricate
data; PWA only, no APK), and a ranked list of known gaps to work on.

`CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md` are one-line pointers back to
`AGENTS.md` so every agent finds it regardless of which convention it looks for.

Two ways to point an agent at the repo:

- **Give it the URL** — most agent tools accept `https://github.com/<you>/<repo>` and clone it.
- **Clone locally and open it** in your editor/agent:
  ```bash
  git clone https://github.com/<your-username>/<your-repo>.git
  cd <your-repo> && code .          # or open the folder in Antigravity
  ```
  Then tell the agent: *"Read AGENTS.md first, then <your task>."*

⚠️ **Two things to tell the new agent explicitly**, or it will waste your time:
- **Run `pip install -r requirements.txt` and `npm install` first** — the repo has no `.venv` or
  `node_modules`, by design.
- **Don't let it "fix" the missing population 60+ / slum-share data by inventing it.** That absence
  is deliberate and is disclosed in `DATA.md`.
