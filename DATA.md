## ⚙️ Modelled (real inputs, constructed relationship)

- **Urban heat island increment (0.0 – 3.5 °C).** Modelled from measured population
  density, green deficit, building density and water deficit; min-max normalised per
  ward set so it is self-calibrating. Capped at 3.5 °C, inside the measured Kolkata
  UHI range of 2–4 °C. Absolute humidity is held constant while temperature rises,
  so relative humidity falls instead of inventing moisture.
- **Risk score (0–100).** `hazard × (0.55 + 0.45 × vulnerability/100)`. The structure
  is standard risk practice (Hazard × Exposure × Vulnerability); the specific weights
  and the hazard exponent are ours, not calibrated against outcomes.
- **Excess mortality.** Real baseline crude death rate (~7.2/1000/yr, India) times a
  population figure that is real, but the dose–response coefficient
  (`RR = exp(0.025 × (WBGT − 27))`) is an assumption. **Illustrative only.**

## ❌ Deliberately missing — and why

These are the inputs a real heat-mortality system needs most, and they are **not
fabricated here**:

- **Population aged 60+ (per ward)** — the single strongest modifier of heat mortality,
  and the one figure with **no machine-readable ward-level source**. The PCA carries age
  only as "population below 6 years", which is a child-dependency signal, not an elderly
  one, so it is deliberately *not* used as a proxy. Absent rather than modelled.
- **Slum / informal household share** — tin and asbestos roofs amplify indoor heat. This
  lives in the Census *slum* tables, a separate product from the ward PCA.
- **Comorbidity, AC access, housing quality, medication use**

What *was* closable, and is now closed: literacy, household size and worker share come
from the official PCA (see the Real table). Vulnerability is now **urban form 0.65 /
social 0.35**, so the index measures exposure, urban form and socioeconomic deprivation
— **not physiological frailty**. The UI states this explicitly rather than implying it.

Options if you want to close the 60+ gap:

1. Parse the DCHB Part-B PDF (censusindia.gov.in, catalog ID `DH_2011_1916_PART_B_DCHB_KOLKATA`)
2. Census C-14 single-year age tables — published for the town, not per ward
3. NFHS-5 or SECC 2011 as a partial proxy (coarser geography)

## ⚠️ Known bias

**OSM completeness varies by ward.** A ward with 3 mapped buildings and 99,000
people/km² is under-mapped, not empty. Green-cover and building-density figures
therefore reflect mapping effort as well as ground truth. A production system should
substitute satellite-derived NDVI (Sentinel-2) and an impervious-surface product.

## Operational data (added in Phase 7)

| File | Rows | Source | Status |
|------|------|--------|--------|
| `data/subscribers.csv` | 23 | **DEMO — placeholder** | Fake numbers (`+9100000xxxxx` / `+9199xxxx`). Seeded by `core.subscribers --seed` so the prototype resolves recipients. **Replace before any live send.** |
| `data/archive/risk_*.csv` | 846 per run | Generated by `scripts/schedule.py` | Real. Every forecast snapshot, keyed by the moment it was made — the only way forecast skill can be measured. |
| `data/processed/scheduler_runs.jsonl` | 1 per cycle | Generated | Real. Cycle log: ward-hours, events found, dispatched, duration, refusals. |
| `data/processed/hindcast_actual_daily.csv` | 4,230 | Open-Meteo archive (reanalysis) | Real. Model replayed on *observed* weather, not forecast. |

### Why `data/archive/` exists

Forecast skill is the difference between what we predicted and what happened.
We never stored predictions, so skill could not be measured retroactively — no
amount of hindcasting fixes missing history. The scheduler now archives every
run; `scripts/hindcast.py` section (B) reports POD/FAR/CSI by lead time once
snapshots are older than the events they predicted (roughly a week of running).

### Deliberately still missing

- **60+ population and slum share** — not in the ward-level Census 2011 PCA
  (age appears only as under-6). The vulnerability index therefore measures
  exposure, urban form and socioeconomic deprivation, not physiological frailty.
- **Real mortality outcomes** — `data/mortality_labels.SYNTHETIC.example.csv` is
  generated *from* the model, so the `R2` that `python -m core.risk --fit` reports
  is circular and means nothing. Supply real ward-level deaths and the weights
  become evidence-based instead of expert-chosen.

## Reproducing the dataset

```bash
# 1. ward polygons
curl -L -o data/geo/kolkata_datameet.json \
  https://raw.githubusercontent.com/datameet/Municipal_Spatial_Data/master/Kolkata/kolkata.geojson

# 2. population (SPARQL: items of class "ward" whose label contains "Kolkata", with P1082)
#    query saved in scripts/ — output: data/wikidata_kmc_population.json

# 3. OSM green/water and buildings via Overpass
#    queries in scripts/build_wards.py header comments

# 4. Census 2011 Primary Census Abstract (official xlsx, via the Wayback Machine —
#    censusindia.gov.in is defunct)
curl -L -o data/raw/census2011_pca_1916.xlsx \
  "https://web.archive.org/web/2020id_/http://censusindia.gov.in/pca/pcadata/DDW_PCA1916_2011_MDDS%20with%20UI.xlsx"

python scripts/build_wards.py        # -> data/wards.csv + data/geo/kolkata_wards.geojson
python -m scripts.build_demographics # -> data/census2011_ward_demographics.csv, merged into wards.csv
python -m scripts.refresh            # re-fetch weather, rebuild thermal + risk tables
```
